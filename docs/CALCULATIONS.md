# 计算合同 v0.1

以下算法用于透明、可重复的估算，不是个人医疗处方。
用户实际身体参数不写入代码。所有固定算例是虚构测试数据。
算法先实现纯 Kotlin 函数，输入显式、输出含单位/版本，UI 不复制公式。

## C01 BMI 与静息代谢

BMI = weightKg / (heightMeters × heightMeters)。
缺少体重/身高或非正值：不计算，返回缺少参数，不返回0。

代谢使用常用简化 Mifflin–St Jeor 形式：
REE = 10×weightKg + 6.25×heightCm - 5×ageYears + sexConstant。
公式男性常数+5，女性常数-161；参数由用户选择，不能由姓名推断。
页面标注“静息代谢估算（常用于基础代谢参考）”，不能叫实测基础代谢。
来源：S01。此为简化形式，版本名 mifflin_simplified_v1。
未成年或适用性不明确时不自动生成建议；仍允许记录和手填目标。
不使用体脂秤单次体脂变化每日自动改目标。

## C02 目标建议与生效

第一版必须同时支持：
1. 手动设置热量与P/F/C目标；
2. 引导估算草稿 → 明确显示参数 → 用户采纳后保存 GoalPeriod。

引导模式：
- 使用最新体重；若不是今天的记录，展示测量日期。
- 用户输入/选择并确认活动系数 PAL，说明它包含通常的日常活动和训练，不能从健身次数自动猜出。
- maintenance = REE × PAL。
- goalType=MAINTAIN：target=maintenance。
- goalType=REDUCE：target=maintenance×(1-deficitPercent)。
- 暂不做增重/竞赛模式；用户仍可手填目标。
- deficitPercent 使用明确可编辑输入，无静默默认；草稿界面可提供10%快捷选项，属于产品选项而不是已确认适合用户。
- proteinG = weightKg×用户确认的蛋白系数；可提供1.6 g/kg快捷参考并链接S02，不把它描述为个人上限或减脂期最优处方。
- fatG = target×用户确认的脂肪能量占比 / 9；占比不暗设为研究结论。
- carbG = (target - proteinG×4 - fatG×9) / 4。
- 任何负碳水、非正热量、比例不合逻辑都返回可修正错误；不钳制成0后假装成功。
- 如果草稿目标低于其静息代谢估算，提示重新检查参数，不自动采纳；该提示只是保守产品检查，不宣称普适生理阈值。
- 用户确认生效日期后保存快照；不要每天因为体重改变自动调整。
- 已有目标时只展示趋势与可选“重新估算”，不自动减餐或加训练。

## C03 食物与营养

按每100g：实际营养 = 基准营养 × 实际克数 / 100。
按每份：实际营养 = 每份营养 × 份数；份数支持小数且>0。
标签kJ转kcal：kcal=kJ/4.184。
优先保存标签给出的能量，不强制用4/4/9覆写标签值。
P/F/C能量占比 = 对应4/9/4折算值 / 三者折算能量总和。
标注“按三大营养素折算”，它可能与标签总热量不同（纤维、舍入等）。
总和为0时占比显示未知，不除0。
份量调整基于日记快照重算；只有用户主动选择“改用食物库最新值”才能替换该条历史快照。

蛋白缺口 = max(目标蛋白 - 已记录蛋白, 0)。
某食物参考份数 = 蛋白缺口 / 该食物每份蛋白。
蛋白粉克数同理；分母<=0不给建议；同时展示新增热量。
提示是备选，不自动添加摄入，不优先绑定某品牌或乳清。

## C04 总消耗与缺口：防重复计算

第一版固定采用“包含通常活动/训练的维持消耗估计”作为基线。
当日估算缺口 = 当日有效 GoalPeriod.maintenance - 当日已记录摄入。
只有饮食日记标为完整且存在维持消耗，才显示“当日估算缺口”；否则显示“仅已记录，暂不评估全天缺口”。
训练能耗单独展示，不再加到此维持消耗上，不用来自动增加可吃额度。
没有maintenance的手动目标：可显示距目标差多少，不能把目标当维持消耗。

运动粗估：
- 需体重、时长和有来源的活动MET；不从重量×次数推导热量。
- 采用 grossKcal = MET×3.5×weightKg/200×minutes；明确为包含该时段静息消耗的粗估。
- 不把短时活动MET无条件应用到整场含长休息的训练；允许直接不估算。
- 来源S03，保存活动代码/描述与版本；首版只收录有核实依据的少量活动。
- 组间长休息、持续时间不确定时提示低可信度，不捏造统计置信区间。
- 同一训练与 ActivityEntry 只关联一份能耗，不重复求和。

## C05 训练比较

- 有效记录 = session已完成 + set已完成 + 非热身 + 数值有效。
- 同器械、同loadKind、同loadConvention才比较。
- 普通外部负重：同重量更多次数；同次数更高重量。
- 助力：同次数更小助力才是更高表现；大助力次数增多不能直接判进步。
- 同一组的重量与次数必须成对保存展示，不拼接两个不同组的“纪录”。
- “上次”显示各组，最好表现可显示多个不可直接排序的组合。
- 第一版不算1RM、不制造统一训练分数、不以总吨位当作增肌疗效。
- 今天复制模板中的未完成组，不计入上次/最好/总量。

## C06 周期统计

- 默认最近7天/30天，含选中结束日；自定义闭区间。
- 体重：先取日代表点，再算窗口内已测天的均值；不足7天显示n/7，不补0。
- 前期对比：7天对前7天，30天对前30天；自定义对比前一个相同天数窗口。
- 无上一期有效数据：显示无法比较，不显示0%。
- 摄入均值：只对用户标完整的日期求平均，并显示完整天数/总天数。
- 训练次数：已完成 session 数；草稿单列，不计完成。
- 训练状态评估只陈述记录变化，不能仅凭体重下降宣称减脂或增肌成功。
