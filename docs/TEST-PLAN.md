# 测试与发布门槛

测试要证明真实行为，不只验证 mock 调用或代码结构。
下面命令以仓库根目录、单 app 模块、debug variant 为前提；首次工程创建后核对实际任务名。

## 测试分层

| 层级 | 内容 | 何时运行 |
| --- | --- | --- |
| 纯JVM单元测试 | 公式、统计、单位、比较、备份DTO校验 | 修改相关逻辑时 |
| Room/Android测试 | DAO事务、迁移、关系、历史快照 | 修改持久化时 |
| Compose UI测试 | 关键录入与状态，不穷举每个装饰组件 | 完成垂直功能时 |
| 真机人工测试 | 键盘、字体、提醒、省电、重启、文件选择器、升级 | 对应阶段及发布前 |
| 文档检查 | 相对链接、任务依赖、状态真实性 | 文档更新时 |

## 标准命令

~~~powershell
.\gradlew.bat :app:testDebugUnitTest
.\gradlew.bat :app:lintDebug
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :app:connectedDebugAndroidTest
~~~

最后一条需要已授权设备/模拟器。只有构建成功而没设备时，不能记录真机通过。
测试报告通常位于 app/build/reports；路径以实际输出为准，不提交带个人数据日志。
测试Task显示 NO-SOURCE 时要写“无用例”，不当作功能通过。

## 必须保留的自动用例

- CALCULATIONS 的V01–V16及缺参、除0、负数边界。
- 目标生效日期与饮食日记快照；删除定义不删历史。
- 复制训练不复制完成状态；草稿恢复；助力与普通负重不混比。
- 事务失败不留下半份套餐/半场训练。
- 所有已发布数据库版本到当前版本的迁移。
- 备份往返、非法输入拒绝、导入失败回滚。
- 通知重复完成幂等，提醒下次发生时间可注入时钟测试。

## E01：离线完整日

前提：使用虚构数据、飞行模式、App没有网络权限。
1. 建本地计算参数并采纳目标。
2. 录体重和可选体脂；确认缺少体脂不阻塞。
3. 添加每100g食物、每份食物和一个套餐。
4. 复制某餐到指定日期，调整份量，确认原日不变。
5. 建两个器械不同的同名动作。
6. 开始训练，完成两组，留一组未完成。
7. 结束，核对仅完成工作组参与比较。
8. 把饮食日记标完整，核对缺口口径。
9. 查看7天与30天，缺测日不出现0体重。
预期：全部不需要登录或联网。

## E02：恢复与编辑

1. 训练过程中退后台、系统终止进程后重开。
2. 草稿、已完成组和未完成组状态保持。
3. 修改食物库数值，旧日记不变，新添加采用新值。
4. 修改今天目标，过去目标不变。
5. 编辑/删除记录，图表和日合计更新，没有残留缓存。
杀进程持久化测试与“强行停止后的通知”是两件事，分别记录。

## E03：提醒实机矩阵

| 场景 | 预期 |
| --- | --- |
| 通知允许、屏幕解锁 | 收到一次提醒，动作可用 |
| 通知拒绝 | 其余功能正常，明确提醒不可用，不反复弹权限 |
| 精确提醒权限未授予/被撤销 | 不崩溃；说明降级状态，不保证准点 |
| 锁屏/Doze/省电 | 记录期望与实际到达时间，不凭推测通过 |
| 手机重启 | 根据配置重排未来提醒，不补发一串旧提醒 |
| 时间/时区改变 | 根据FOLLOW_DEVICE规则安排下一次，历史不重排 |
| 连续点两次“完成” | 仅一条完成记录 |
| 稍后提醒后再完成 | 取消该次延后通知，不取消明天 |
| 系统强行停止 | 明确系统限制；重新打开后重排，不承诺强停后仍触发 |
| 导入备份 | 不恢复旧系统通知ID；提示检查权限与启用 |

开发时可用几分钟后的虚构提醒；真正的隔夜/重启/省电结果由实机记录。
小米具体自启动设置按实际型号与系统验证，文档不写死不适用菜单。
不让功能必须依赖常驻前台服务。

## E04：备份与换机模拟

用备份规格所有实体创建虚构数据A。
导出A → 修改本机成B → 导入预览A → 取消，仍为B。
再次导入确认 → 成为A；所有ID/历史快照与原A一致。
损坏文件、重复ID、未知版本和事务中断均不改变当前数据。
可在第二台模拟器/同一设备不同测试安装中完成恢复，不要求真正买新手机。

## E05：界面

- 窄屏、360dp、大屏、横屏、键盘弹出，布局可操作。
- 100%/150%/200%字号，主要路径可滚动，无按钮被遮。
- 颜色对比度与TalkBack顺序；图表有文字摘要。
- 只用虚构数据截图，真实手机通知栏/账号信息打码后再公开。
- 录完一组不需要跳三个页面；常用食物能快速加入。
- 空列表、长名称、加载、保存失败都可理解。

## E06：安装与升级

- debug开发包与长期release包有清楚的身份。
- 签名文件在仓库外安全备份；Git只包含配置模板。
- 用同一release签名和包名安装vA，写虚构数据；提高versionCode构建vB并覆盖安装。
- 验证体重、目标、日记、训练、提醒设置保留；不能卸载后重装来宣称升级成功。
- 记录APK SHA256与版本号，包留本地，不上传公开Release，除非用户要求。
- 密钥丢失不能用新密钥冒充可直接更新；先解释恢复路径。

## 首个完整自用版发布门槛

全部满足才能标记T28 DONE：
- 核心计算与数据库/备份自动测试通过。
- debug build、lint通过；release构建与签名检查通过。
- E01、E02、E04、E05、E06有实测记录。
- E03实际支持范围与限制记录清楚，关键提醒没有未解决阻塞。
- 使用者确认基本视觉和录入流程可用；未反馈如实保留。
- 已完成T27试用或用户明确同意提前结束试用。
- 没有公开个人数据、密钥、真实备份；没有意外网络权限或付费SDK。
- 远程备份仍待定时，在版本说明中明确列为未实现。

## 验证记录模板

任务ID / 日期 / commit / 设备（只写型号与系统，不写序列号）/ 操作或命令 /
预期 / 实际 / PASS或FAIL或NOT_RUN / 证据文件或简短日志 / 剩余问题。
