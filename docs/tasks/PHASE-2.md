# 阶段2：本地数据、计算与身体目标

## T07 Room数据库和Repository

输入：DATA-MODEL、ARCHITECTURE、ENVIRONMENT。
操作：
1. 根据实际工具链选择兼容稳定Room/KSP，记录版本和包名系列。
2. 建实体与DAO，按关系建立索引和约束；数据库操作异步。
3. 创建AppContainer与按领域划分的Repository；ViewModel只通过Repository读写。
4. 导出schema JSON到app/schemas并提交。
5. 未有实现的UI不接假数据回退，展示明确空状态。
产出：Room数据库、DAO、Repository基础、schema。
验收：构建；虚构数据插入/查询/约束测试；DAO无主线程访问。
边界：不加云数据库或网络同步表；不使用destructive migration。
下一项：T08。

## T08 历史快照、事务和迁移策略

输入：DATA-MODEL、BACKUP-FORMAT、Room官方迁移资料。
操作：
1. 实现食物加入日记的营养快照与套餐事务。
2. 实现目标按生效日期查找、动作比较身份快照、字典归档。
3. 建数据库版本变更流程；初版schema留档。
4. 通过事务失败注入验证半份套餐不会落盘。
5. 如果尚无旧数据库版本，不制造虚假迁移测试；记录首版基线，第一次结构变化补上真实迁移测试。
产出：一致性规则与有意义的数据库测试。
验收：改字典不改旧记录；归档不删历史；事务失败不留部分数据。
下一项：T09。

## T09 纯计算与算例

输入：CALCULATIONS全篇、SOURCES。
操作：
1. 建纯Kotlin函数，分别处理BMI/REE、目标草稿、食物缩放、蛋白缺口、能耗、训练比较、统计窗口。
2. 注入Clock/日期，禁止函数自己读取“今天”。
3. 为V01–V16写固定期望值测试；补缺参、零分母、负数和跨日边界。
4. 所有单位转换集中处理，内部不逐步过早取整。
5. 能量建议返回草稿与参数，不能自动覆盖当前目标。
产出：core/calculation及单元测试。
验收：单元测试通过；至少人工复算V03/V04/V08一次；UI没有复制公式。
停止：研究依据不足或新算法提议写待定，不发明健康结论。
下一项：T10。

## T10 身体记录垂直功能

输入：PRODUCT、DATA-MODEL、C01/C06。
操作：
1. 接通体重/可选体脂/可选腰围录入，身体计算参数放本地设置。
2. 保存到Room，再通过Flow刷新页面。
3. 支持同日多次、查看历史、修改和删除；日趋势取最后一次有效值。
4. 参数缺失显示“待设置”，仍允许记录体重。
5. 重启App验证持久化。
产出：第一条完整“UI→DB→UI”功能。
验收：录入/编辑/删除及进程重启测试；BMI固定算例正确；体脂缺失不补0。
下一项：T11。

## T11 目标草稿与历史

输入：C02/C04、GoalPeriod定义。
操作：
1. 实现手动目标与引导估算两种方式。
2. 明确显示体重日期、公式、活动系数、缺口、蛋白与脂肪参数。
3. 缺参数不计算；负碳水/冲突比例给出修正提示。
4. 采纳前展示草稿，采纳后保存输入快照和生效日期。
5. 历史日期读取当时目标；今天体重改变不自动改所有目标。
6. 手动目标没有maintenance时，只显示目标差额，不算全天缺口。
产出：设置与目标建议闭环。
验收：草稿取消不写库；生效前后日期目标不同；V03/V04/V08/V09/V16通过。
下一项：T12。
