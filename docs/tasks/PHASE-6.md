# 阶段6：数据可带走、界面可长期使用

## T21 通用文件导出

输入：BACKUP-FORMAT、DATA-MODEL。
操作：
1. 建独立备份DTO/序列化器，和Room Entity解耦。
2. 在一致性事务内读取完整数据，包含草稿和历史快照。
3. 生成私有临时文件并自身校验。
4. 系统文件选择器导出；明确v1为明文个人数据文件。
5. 仅关闭输出流成功后显示完成；取消/失败不改记录和成功时间。
6. 建每类实体都有内容的虚构golden fixture。
产出：文件备份能力，不是云同步。
验收：序列化往返、空数据、中文、小数/单位、取消写出；不把真实文件提交Git。
下一项：T22。

## T22 备份导入与替换

输入：BACKUP-FORMAT、T21。
操作：
1. 流式限制大小，再解析校验版本、ID、关系、字段。
2. 展示内容与数量预览，明确将替换本机数据。
3. 提供当前数据导出入口，取得用户此次替换确认后才执行。
4. Room事务内替换；失败回滚，绝不先清库后解析。
5. 导入成功后刷新UI并处理旧系统提醒，检查权限再启用新计划。
6. 重复导入按替换结果一致，不实现合并逻辑。
产出：换机可用的恢复流程。
验收：E04、恶意/损坏文件、未知版本、重复ID、孤儿记录、事务失败；拒绝时本机不变。
下一项：T23。

## T23 权限、隐私与生命周期检查

输入：ARCHITECTURE、TEST-PLAN、AndroidManifest与依赖树。
操作：
1. 检查manifest合并结果，只保留当前功能需要的权限。
2. 本地版本没有网络/广告/分析SDK；不请求所有文件访问权限。
3. 显式配置系统备份/设备转移策略。初版原则为不依赖系统云备份；必要时设allowBackup/dataExtractionRules并实测，厂商差异如实记录。
4. 检查日志、截图、fixture、Git暂存内容不含私人数据或密钥。
5. 私有临时导出文件及时清理；不要清理用户选定的外部备份。
6. 设置界面写明数据位置、卸载风险和文件导出范围。
7. 再验证杀进程、旋转、返回与重复点击状态。
产出：明确权限和数据边界的App。
验收：manifest/依赖人工检查，E02关键用例，本地功能飞行模式可用。
下一项：T24。

## T24 UI收敛、可访问性与性能

输入：DESIGN-SYSTEM、完整功能页、E05。
操作：
1. 移除生产路径的Fake数据，统一卡片、数值、按钮、空状态和错误提示。
2. 检查渐变、留白、长名称、小屏、键盘和字体放大。
3. 检查对比度、TalkBack语义和至少48dp点击目标。
4. 使用一年虚构记录检查图表与列表，优化慢查询/重复计算，不提前引入缓存服务。
5. 查看明显主线程阻塞、重复重组、列表key问题。
6. 展示可运行完整页面截图供用户反馈，明确反馈是否已收到。
产出：视觉一致且可操作的第一版。
验收：E05，无关键卡顿/遮挡；不靠缩小字体“修复”布局；记录未解决审美反馈。
下一项：T25。
