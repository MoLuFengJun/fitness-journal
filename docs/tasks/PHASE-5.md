# 阶段5：总览与本地提醒

## T18 Dashboard周期统计

输入：C06、PRODUCT、DESIGN-SYSTEM。
操作：
1. 将总览假数据替换为真实本地查询。
2. 接通今天的能量、蛋白、体重、训练与提醒状态。
3. 实现7天/30天/自定义区间，前一等长窗口对比。
4. 体重原始点与窗口均值、完整饮食日摄入均值、训练次数和指定动作趋势。
5. 标明有效记录天数；缺测是空缺；不计算分母0的变化率。
6. 图表有文字摘要/可读列表，不只显示线和色块。
7. 一个日期/记录变化后相关图表自动刷新，不维护第二套易失汇总。
产出：可辅助观察的总览。
验收：V11/V12及跨月窗口、无上期数据、缺测日；数据量增大仍可交互。
下一项：T19。

## T19 提醒设置与权限

输入：提醒实体、ARCHITECTURE、Android A13/A14。
操作：
1. 设置中允许自定义名称、时间、星期、启用状态；不预置真实个人药名。
2. 首次启用时申请通知权限；拒绝可继续使用其他功能。
3. 精确到点需要对应权限时引导；未授权用明确可解释降级，不假称准时。
4. 创建通知channel；系统权限与App开关分别显示。
5. 实现可注入时钟的“下一发生时间”函数，覆盖跨日/周末。
6. 用系统AlarmManager安排单次下一提醒；不用WorkManager或常驻循环模拟闹钟。
产出：设置与可触发的测试提醒。
验收：几分钟后的虚构提醒；权限拒绝不崩；开关关闭取消对应提醒。
停止：无设备记录NEEDS_DEVICE_CHECK。
下一项：T20。

## T20 通知动作与恢复调度

输入：T19、ReminderOccurrence、TEST-PLAN E03。
操作：
1. 通知提供完成、稍后提醒；App内可查看/修改完成状态。
2. PendingIntent标识唯一且遵守平台要求，重复动作幂等。
3. 完成只结束该次提醒；稍后提醒只更改该次，不改变每日计划。
4. 重启、时区/时间变化、权限恢复、App重新打开后重排未来提醒。
5. 变更或删除计划取消旧通知；过去未完成标记保留，不补发旧通知风暴。
6. 写清强行停止和系统限制，不承诺绕过系统。
7. 在小米锁屏/省电/重启状态记录实际时间。
产出：提醒动作与调度恢复闭环。
验收：E03矩阵；重复完成只有一条；完成后延后通知取消；明天仍有计划。
停止：未实测场景记NEEDS_DEVICE_CHECK，允许独立开展T21；T28前必须处理。
下一项：T21。
