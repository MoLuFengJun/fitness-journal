# 阶段3：吃

## T12 常用食物与套餐

输入：FoodDefinition/MealTemplate、PRODUCT、C03。
操作：
1. 实现每100g与每份两种食物定义；填名称、单位、能量和P/F/C。
2. 支持标签kJ换算、来源标记（标签/人工估算），不编造外食精确数据。
3. 自定义套餐由多项食物和份量组成，可调整某一项。
4. 常用/最近使用查询，支持归档。
5. 示例仅放测试/预览；正式库初始为空，不搬入真实个人饮食。
产出：食物库、套餐编辑与选择页。
验收：每100g与每份缩放正确；无蛋白食物不导致除0；归档仍保留历史。
下一项：T13。

## T13 每日饮食日记

输入：T12、FoodEntry/DayLogState、C03/C04。
操作：
1. 按日期与餐次添加食物/套餐，支持小数份量。
2. 保存时拍营养快照；套餐在同一事务中加入。
3. 支持编辑、删除、复制某餐；复制前确认目标日，避免误点重复。
4. 接通当天总能量与P/F/C，显示“已记录”。
5. 增加当日日记完整标记，默认未完整。
6. 饮食修改后取消原完整标记或明确让用户重新确认，采用一种规则并写测试；默认取消标记。
产出：日记与营养合计闭环。
验收：V05/V06/V15；过去记录不随食物库变化；复制不改原日；取消完整后不显示全天缺口。
下一项：T14。

## T14 蛋白剩余与补充换算

输入：C03、食物库和当日目标。
操作：
1. 显示还差多少蛋白、当前剩余热量。
2. 从用户常用食物中选择蛋白来源，展示参考份量及新增热量。
3. 粉类按产品标签算克数，不把粉重等同蛋白重。
4. 没有目标/没有有效蛋白来源时给出设置入口。
5. “加入日记”是明确按钮，查看建议不能自动记已吃。
产出：饮食页的补充参考功能。
验收：V07、已达标时缺口为0、分母0无建议、建议加入后才改变日记。
边界：不强制某种食品，不联网生成食谱，不把建议称为医学处方。
下一项：T15。
